# 会议记录 - 2026/06/17

## 会议背景

团队围绕文献分析与数据提取工具的使用反馈，讨论了结果缺失、输入体验、变异标准化和家系信息补全等问题。目标是提升基因位点、转录本和家系验证信息的识别准确率，并降低用户输入成本。

---

## 一、内容生成与信息差异问题

### 1.1 生成内容与表格差异

- **发言人2**：当前工具生成的内容相比表格存在明显缺失，主要集中在患者家系情况未被提取。
- 工具虽能识别 PM3 证据和 PS（含 PS3），但未覆盖父母验证结果、患者是否携带目标变异等关键信息。
- 患者年龄已提取，但家族遗传验证状态缺失，影响最终结论判断。
- **发言人1**：强调最后结论中必须包含是否通过父母验证的判定依据。

### 1.2 文献总结机制缺陷

- **发言人2**：当工具未能识别目标位点时，输出为空，无法区分是无结果还是未识别。
- 建议即使未找到位点，也应生成基础文献总结，便于人工判断。
- **发言人1**：该功能更适合作为 PDF 预处理环节实现，而非每次手动调用。

### 1.3 家系抽取内容扩展

家系信息抽取需扩展为四个维度：

1. **家系其它成员关系**（如父母、兄弟姐妹、子女等亲属关系）
2. **表型状态**（受影响 / 未受影响 / 未知）
3. **携带位点状态**（是否携带目标变异）
4. **变异分布结果**（如父母来源、新发突变、家系内分布规律）

## 二、输入界面优化建议

### 2.1 当前输入问题

- **发言人2**：现有输入格式为一大串文本，易出错（如括号遗漏、冒号缺失）。
- 用户需自行拼接基因、核苷酸、氨基酸、转录本号等信息，操作繁琐、容错低。

### 2.2 结构化输入方案

- **发言人2**：建议拆分为独立字段，包括"转录本号"、"基因"、"cDNA 点突变（C点）"、"蛋白点突变（P点）"、"染色体位置"、"rs号"等。
- 字段需区分必填与选填，例如"转录本 + C点"或"转录本 + P点"为必填组合，基因可与转录本二选一。
- **发言人1**：系统可自动拼接标准格式，并展示示例结果，降低格式错误。

### 2.3 智能映射与默认顺序

- **发言人2**：系统应支持根据部分信息自动补全其余字段（如输入基因和 C 点后反推 P 点）。
- 不同转录本可能对应多个映射，建议优先搜索常用主转录本；若未匹配成功，再遍历其他转录本。
- **发言人1**：若用户提供括号内具体转录本编号，优先使用；未提供则按预设顺序尝试。

### 2.4 变异标准化输入规则

基因组版本：**默认 GRCh37**，**可选 GRCh38**。系统应支持以下五种标准输入格式：

| 标准 | 输入格式 | 示例 |
|------|----------|------|
| 标准1 | 转录本 + c. | `NM_004004.6:c.1521_1523del` |
| 标准2 | 转录本 + p. | `NM_004004.6:p.Val37Ile` |
| 标准3 | 基因 + c. | `GJB2:c.235delC` |
| 标准4 | 基因 + p. | `GJB2:p.Val37Ile` |
| 标准5 | 基因组坐标 + HGVS | `chr13:32936732C>T` |

### 2.5 补充搜索支持

除五种标准格式外，系统还应支持：

- **dbSNP 编号搜索**：输入 `rs` 号即可定位对应变异。
- **自由文本兜底搜索**：对不确定或非标准描述（如 `chr7q31 deletion`、`IVS2-1G>A` 等）应能识别并尽量匹配。

## 三、系统数据调用与染色体组问题

### 3.1 染色体组输入障碍

- **发言人2**：当前工具要求输入染色体组版本（如 hg19/hg38），但云平台界面未展示该信息，用户难以查找并填写。
- **发言人1**：确认云平台已有基因与转录本对应关系数据。
- **发言人2**：建议直接调用内部转录本数据库，省去用户手动查询；文献中极少出现染色体组版本信息，可弱化该字段。

### 3.2 综合数据源使用

- **发言人1**：可结合外部工具与内部数据共同支持解析。
- **发言人2**：内部数据更贴合业务场景，优先级高于外部通用字段。

## 五、关键决策与共识

1. **信息补全**：最终结论必须包含患者是否通过父母验证及其依据。
2. **家系抽取扩展**：家系信息抽取需覆盖四维度——成员关系、表型状态、携带位点状态、变异分布结果。
3. **输入重构**：推动输入界面由单行文本改为结构化字段，支持自动拼接与示例提示。
4. **变异标准化输入**：采用五种标准格式（转录本±c./p.、基因±c./p.、基因组坐标+HGVS），默认 GRCh37，可选 GRCh38。
5. **搜索策略**：以用户提供的主转录本为首选进行匹配，失败后再按顺序尝试其他转录本。
6. **数据调用优先级**：优先使用内部系统已有的转录本与基因对应关系，减少对外部染色体组字段依赖。
7. **补充搜索**：支持 dbSNP `rs` 编号检索，以及 `chr7q31 deletion` 等自由文本的兜底匹配。

## 七、AI 洞察

- 当前工具在临床关键信息（如家系验证状态）提取上存在结构性缺失，仅依赖 PM/PS 证据可能导致误判风险。
- 用户输入负担重的根本原因在于"格式耦合"——必须手工维护复杂命名规范，结构化输入 + 自动拼接是从根源降本增效的关键。
- 将染色体组设为必填项违背实际使用场景，文献中罕见该信息，反映工具设计未充分对齐真实数据来源。
